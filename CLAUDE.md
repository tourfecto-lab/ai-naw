# Tourfecto (tourfecto.pro)

PHP SaaS (no framework) for tourism / local businesses: SEO + AI visibility, WhatsApp/Messenger/Instagram AI chat,
social publishing, ads, creative studio, CRM, bookings/payments, reputation (Google Business), white-label agencies.

## Layout
- `public_html/index.php` is the web front controller (a root `index.php` also exists; the deployed docroot is not
  verified from this repo, so do not delete root-level PHP files without checking the server).
- `app/Controllers` (~140), `app/Services/<Domain>`, `app/Models`, `app/Jobs`, `app/Core`, `app/Security`.
  Routes: `app/routes/{web,api,webhooks}.php`. HTML for admin/dashboard is built as strings inside controllers
  (`app/Core/Controller.php` wraps it); only Settings/AiInsights/AiVisibility/social have real view files.
- Autoload: Composer classmap + `app/Config/project_classmap.php` (generated by `tools/build_project_classmap.php`)
  + explicit `require_once` lists in `public_html/index.php`. A new class must be added to the classmap.
- Migrations: `database/migrations/*.sql` (hand-applied on the server; no runner). `database/schema.sql` is the old base schema.
- i18n: `app/Lang` (server) and `public_html/assets/i18n/*-dict.js` (client text swap). Comments and UI strings are
  mostly Egyptian Arabic.
- Cron entry points are in `cron/`. Root-level `scheduler.php`, `schedule.php`, `run_automations.php`, `bootstrap.php`
  are stray copies; `run_automations.php` requires the root `bootstrap.php` (which is a test bootstrap).

## Commands (Windows dev box uses XAMPP PHP 8.2 + MariaDB; CI uses PHP 8.2 + MariaDB 10.11 (production is very likely MariaDB: the migrations use MariaDB-only `ADD COLUMN IF NOT EXISTS`))
- Install: `composer install`
- Syntax: `git ls-files '*.php' | grep -v '^vendor/' | xargs -n40 php -l`
- Static analysis: `vendor/bin/phpstan analyse --memory-limit=2G` (level 1 + `phpstan-baseline.neon`; Controllers and
  Services are too large for PHPStan memory, so they are not analysed yet)
- Tests: create DB `tourfecto_test`, then
  `DB_HOST=127.0.0.1 DB_NAME=tourfecto_test DB_USER=root DB_PASS= vendor/bin/phpunit --configuration tests/phpunit.xml`.
  `tests/bootstrap.php` applies every `database/migrations/20*.sql` in order (statement by statement, only against
  `tourfecto_test`; `TOURFECTO_TEST_MIGRATION_MODE=legacy` restores `schema.sql` + a manual list). `php tools/migration_report.php`
  lists the failing migration statements; see `docs/ops/MIGRATION_CHAIN_GAPS_AR.md`. Tests run in random order; use `--order-by=random --random-order-seed=N` when comparing runs.
  Baseline (2026-10-28, seed 1793197154, CI + local agree): 1147 tests, 95 failing (Creative Studio funding fixtures, OTA revenue,
  Outreach, SEO rank tracking, TikTok v2, a few email tests). CI fails if that number exceeds `MAX_KNOWN_FAILURES` in ci.yml; lower it as tests get fixed.

## Rules for changes
- Deployment to the live server is manual (upload). Never change live config, secrets, or the production DB from here.
- Do not touch Meta / WhatsApp / Google OAuth scopes, redirect URIs, webhook paths or verify tokens, data-deletion and
  deauthorize callbacks, privacy/terms pages, or the connect/publish/reply screens while the Meta app review and the
  Google OAuth verification are pending.
- Security conventions already in the code: prepared statements everywhere; `RequestOriginGuard` (origin-based CSRF) plus
  `verifyCsrf()` on state-changing controller actions (token via `csrf_token` field or `X-CSRF-Token` header);
  `SafeHttp`/`SsrfGuard` for any server-side fetch of user-supplied URLs; webhooks verify signatures with `hash_equals`.
- Migration `2026_07_14_000007b_merge_modules_unified_schema.sql` drops `'user'` from `users.role` despite its comment;
  do not run it on a DB that has `user` roles.
- `app/app/` and other stale duplicate copies were removed; do not reintroduce a second copy of `app/`.
