تحديث فحص صحة المنصة — تسويق المنصة

خد نسخة من الملفين الحاليين، ثم ارفع الملفين التاليين مع الحفاظ على المسارات داخل جذر موقعك:
app/Services/Admin/PlatformHealthService.php
public_html/assets/js/admin-insights.js

افتح /admin/health واعمل تحديث كامل للصفحة (Ctrl+Shift+R).
هيظهر قسم «تسويق المنصة: ليه الإرسال واقف؟» بعد فحوصات الكرون.
مفيش migration مطلوبة لتثبيت الفحص. لو الفحص كشف جدولًا ناقصًا، اتبع الإجراء الظاهر؛ الفحص نفسه لا ينشئه.
الفحوصات تشخيصية: لا تغيّر الإعدادات ولا تبعت رسائل.
الكود تم اختباره محليًا ولم يتم نشره على سيرفر الإنتاج.

الفحص يراجع كرون platform_outreach ونبضة المنظّم، تشغيل الحملة، المنطقة الزمنية والمواعيد وأيام الاستثناء، SMTP الفعلي للحملة وفك التشفير، صيغة عنوان المرسل ورابط التسجيل، جاهزية الشركات والموافقات والمتابعات، الحد اليومي، الرسائل الفاشلة، حماية الراجع، وتعذر قراءة الجداول.
فحص SMTP في هذا القسم لإعداداته فقط؛ لا يثبت اتصالًا أو تسليمًا فعليًا. نجاح تنفيذ الكرون لا يثبت إرسال رسالة.

tools/test_outreach_health.php ملف اختبار اختياري لسطر الأوامر فقط.
لتشغيله على قاعدة MySQL اختبار قابلة للتخلص منها:
TEST_DB_DSN='mysql:host=HOST;dbname=TEST_DATABASE;charset=utf8mb4' TEST_DB_USER=TEST_USER TEST_DB_PASS=TEST_PASSWORD php tools/test_outreach_health.php
استخدم بيانات قاعدة الاختبار محليًا؛ لا ترسل كلمات المرور في المحادثة. الاختبارات تستخدم جداول TEMPORARY في نفس الاتصال.
نتيجة الاختبار المحلي: 27 فحصًا ناجحًا. نجح فحص صياغة PHP وJavaScript وتوليد تقرير صحة المنصة كاملًا.
